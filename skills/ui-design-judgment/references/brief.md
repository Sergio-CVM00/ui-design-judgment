# Design intention

Record this before composition or critique. Reuse existing requirements instead
of adding another document when they already answer these questions.

| Field | Record |
| --- | --- |
| Audience and context | Who uses this view and under what conditions? |
| Primary task | What decision or action should become easier? |
| First focus and reading order | What should draw attention first, then next? |
| Content | Real labels, representative data, long text and meaningful states |
| System | Tokens, typography, components, density, interaction patterns |
| Constraints | Platform, accessibility target, performance, scope and authority |
| Scope | Routes, viewport sizes, states and primary task journey |
| Acceptance | Observable behavior and contextual design expectations |
| Assumptions | Inferences that have not been confirmed |

A revenue-monitoring dashboard may emphasize revenue trend and exceptions. An
order-resolution console may prioritize actionable rows, urgency and filtering.
The same arrangement can be appropriate for one task and distracting for another.
